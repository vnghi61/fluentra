## 2. The four traps

### Trap 1 — `content_version_id` cannot be a foreign key

`/DATABASE_GUIDELINE.md` **DB4**: *the only cross-schema foreign key permitted is
`→ core.users(id)`.*

`learn.activities.content_version_id` points at `content.content_versions.id`. That is a
different schema and it is not `core.users`, so:

```sql
-- WRONG. Postgres accepts it. The rule does not.
content_version_id uuid NOT NULL REFERENCES content.content_versions(id)

-- RIGHT.
content_version_id uuid NOT NULL
```

Nothing fails at migration time, which is exactly why this one gets shipped. The column is a
bare `uuid`, and referential integrity becomes the service's job — resolve through
`content.Reader`, and let **BR-LESSON-02** do the enforcing at publish time.

`db/migrations/content/schema_integration_test.go` is the file to copy — but read it before
you assume it covers this. `TestContentSchema_EveryForeignKeyIsIndexed` asserts FK
**indexing**; nothing in the repository asserts DB4 itself yet. Write that assertion for
`learn`, because a rule with no test is a rule that holds until someone is in a hurry:

```sql
SELECT t.relname, c.conname, fn.nspname AS target_schema, ft.relname AS target_table
FROM pg_constraint c
JOIN pg_class t       ON t.oid  = c.conrelid
JOIN pg_namespace n   ON n.oid  = t.relnamespace
JOIN pg_class ft      ON ft.oid = c.confrelid
JOIN pg_namespace fn  ON fn.oid = ft.relnamespace
WHERE c.contype = 'f' AND n.nspname = 'learn';
```

Every row must have `target_schema = 'learn'`, or `core` with `target_table = 'users'`.

The same applies to `sqlc.yaml`. The `lesson` entry needs `_bootstrap`, `user` **and**
`content` under `schema:` so sqlc can resolve types, but that is a compile-time convenience,
not a licence to write the constraint.

### Trap 2 — `lesson` may not import `learning`

`.go-arch-lint.yml` says:

```yaml
m_lesson:   { mayDependOn: [p_cache, p_telemetry, c_content] }
m_learning: { mayDependOn: [p_cache, p_job, p_telemetry, c_lesson, c_content, c_srs] }
```

`c_learning` is **not** in `m_lesson`'s list, and `internal/modules/learning/contract/` holds
nothing but a `doc.go` — `UnlockChecker` does not exist yet and lands in P8.1.

Two documents will push you the wrong way. `learning/AGENT.md` §4 describes
`learning.UnlockChecker` as "used by `lesson`", and WP7 says "implement unlocking via
`learning.UnlockChecker`". Read literally, both would have you import `c_learning`, add it to
arch-lint, and block P7.4 on a WP8 task.

**Do neither.** Define the interface where it is consumed, which is this repository's
existing pattern — `content` does exactly this with `Guard`:

```go
// internal/modules/lesson/service/service.go

// UnlockChecker answers whether a learner has met a lesson's prerequisites.
// learning implements it; lesson only calls it, so the interface is declared
// here rather than imported, and lesson does not depend on learning.
type UnlockChecker interface {
    IsUnlocked(ctx context.Context, userID, lessonID uuid.UUID) (bool, error)
}
```

`cmd/api/modules.go` satisfies it at wiring time, the way `lazyGuard` satisfies
`content.Guard`. Until WP8 lands, wire a nil-safe default that reports every lesson unlocked
and say so in `lesson/DECISIONS.md`. Do not edit `.go-arch-lint.yml`'s dependency lists to
make an import legal.

### Trap 3 — the lock reason is a string the API returns

`LessonSummary` in the spec has both `locked: boolean` and `lock_reason: string | null`, and
the example reads `"Complete Unit 1 Lesson 2 first"`. That wording is generated **here**, not
in the UI. A boolean alone forces the frontend to invent copy, and it will invent different
copy on three screens.

The reason names the specific missing prerequisite, so it needs the prerequisite lesson's
title — which means the unlock query resolves titles, not just ids.

### Trap 4 — resolve content in one query, and prove it

`content.Reader.GetManyVersions` exists precisely so a lesson with twelve activities costs
one round trip. Calling `GetVersion` in a loop is the failure this contract was designed
against.

P7.3's query-count test was a tautology — the fake repository incremented its counter in
exactly one method, so the assertion could not fail on the N+1 it existed to catch. If you
write a counting fake, **every** method increments, and the assertion is on a constant number
you can justify.

## 3. What to build

Split by layer, the way `content` is. `.go-arch-lint.yml` currently has `m_lesson` as one
component; replace it with five and add the generated one:

```yaml
components:
  m_lesson:            { in: modules/lesson }
  m_lesson_domain:     { in: modules/lesson/domain }
  m_lesson_repository: { in: modules/lesson/repository }
  m_lesson_service:    { in: modules/lesson/service }
  m_lesson_http:       { in: modules/lesson/transport/http }
  g_lesson:            { in: generated/lesson/sqlc }

deps:
  m_lesson_repository: { mayDependOn: [m_lesson_domain, c_lesson, g_lesson] }
  m_lesson_service:    { mayDependOn: [m_lesson_domain, c_lesson, c_content] }
  m_lesson_http:       { mayDependOn: [m_lesson_domain, m_lesson_service, c_lesson] }
  m_lesson:            { mayDependOn: [m_lesson_domain, m_lesson_repository,
                                       m_lesson_service, m_lesson_http, c_lesson, c_content] }
```

### Schema — `db/migrations/lesson/1700000200_create_lesson_tables.sql`

Five tables, schema `learn`, exactly the ones `AGENT.md` §5 declares. No more.

| Table | Notes |
|---|---|
| `courses` | `slug` UNIQUE, `cefr_from`, `cefr_to`, `status`, `estimated_hours` |
| `course_units` | `course_id`, `position`, `title`; unique on `(course_id, position)` |
| `lessons` | `unit_id`, `position`, `skill_focus`, `estimated_minutes`, `status` |
| `activities` | `lesson_id`, `position`, `kind`, `content_version_id`, `config` jsonb, `weight` |
| `lesson_prerequisites` | `lesson_id`, `requires_lesson_id`, `min_score` |

Reversible down. Every FK indexed. `status` is the same three-value enum the spec declares
(`draft`, `published`, `archived`).

`lesson_prerequisites` needs a self-reference guard: `CHECK (lesson_id <> requires_lesson_id)`
catches the one-node cycle in the database, and the DAG check in the service catches the
rest — a check constraint cannot walk a graph.

### Domain

- Ordering and position invariants
- **BR-LESSON-03** cycle detection over the prerequisite graph, as a pure function with a
  table-driven test: no edges, a chain, a diamond, a two-node cycle, a three-node cycle, a
  self-edge, and a new edge that closes an existing chain
- **BR-LESSON-06** estimated duration is the sum of activity estimates, recalculated on
  change
- Error codes exactly as `lesson/AGENT.md` §12 lists them:

| Code | Status |
|---|---|
| `LESSON_LOCKED` | 403 |
| `PREREQUISITE_CYCLE` | 422 |
| `ACTIVITY_CONTENT_UNPUBLISHED` | 409 |

Every illegal operation returns one of these through `shared/apperr`. Not a 500, and not a
bare wrapped error — P7.3 shipped `ErrContentInUse` declared and never returned; do not leave
a code in `errors.go` that no path produces.

### Service

- `lesson.Reader`: `GetLesson`, `ListLessons`, `NextLesson`, per the contract P7.1 landed
- Activity content resolved through `content.Reader.GetManyVersions`, batched
- **BR-LESSON-02**: publish is refused while any activity points at content that is not
  published. Note the shape of the check — `content_versions.status = 'published'` is not
  sufficient on its own, because an archived item keeps a published version. See
  `content/DECISIONS.md`: the learner-facing reads join `content_items` and filter there too,
  and so must this one.
- Unlocking evaluated through the locally-declared `UnlockChecker`, producing the reason
  string from Trap 3

### Transport

The five paths already in the spec, no others:

| Method | Path | Permission |
|---|---|---|
| `GET` | `/api/v1/courses` | `content.read.published` |
| `GET` | `/api/v1/courses/{slug}` | `content.read.published` |
| `GET` | `/api/v1/lessons/{id}` | `content.read.published` |
| `POST` | `/api/v1/admin/courses` | `content.create` |
| `PUT` | `/api/v1/admin/lessons/{id}/activities` | `content.edit` |

Learner routes mount on the authenticated router; admin routes mount behind
`rbac.AdminOnly()`. Copy the wiring in `cmd/api/modules.go` that P7.3 added for `content`,
including the fail-closed `NewHandler` that refuses a nil guard.

**Any list endpoint takes a bounded page size.** `DefaultLimit = 20`, `MaxLimit = 100`,
clamped in `int` space **before** the conversion to `int32` — `internal/modules/content/domain/paging.go`
has the helper and the reasoning. CodeQL failed P7.3's PR over exactly this, and a `#nosec`
comment asserting a bound that does not exist is worse than no comment.

## 5. Definition of Done — the parts P7.3 got wrong

Everything in [phase-2-plan.md](../phase-2-plan.md) §2.3 applies. These five are called out
because the last task missed each of them and the PR went red or the review sent it back.

1. **`make check` is not the whole check.** CI runs a second lint pass that `make check` does
   not:

   ```bash
   golangci-lint run --build-tags=integration ./...
   ```

   Files behind `//go:build integration` are invisible to the default run, so every
   container-backed test is unlinted until this command sees it. P7.3 failed CI with fifteen
   findings in one integration test file.

2. **Coverage is measured, not estimated.** `make cover-check` needs Postgres and Redis.
   State the printed figure. "Approximately 40%" in a commit message that the gate reads as
   33.3% is how a task ships under its acceptance bar.

3. **One task, one diff.** P7.3's commit carried `.agents/skills.json`, `AGENTS.md` and
   `GEMINI.md` edits pointing at a machine-local path. Agent tooling configuration is not
   part of a feature commit. If a formatting or dependency change is genuinely needed, it is
   its own commit with its own message.

4. **A test that cannot fail is not a test.** State the failure it is designed to catch, then
   check that the test would actually catch it.

5. **A suppression comment is a claim.** `#nosec`, `//nolint`, `eslint-disable` — each one
   asserts something about the code. If the assertion is false, the comment has hidden a real
   bug from the tool built to find it. Prefer restructuring the code so the suppression is
   unnecessary.

Before you finish:

```bash
make check
golangci-lint run --build-tags=integration ./...
make cover-check
make docs-check
```

Then update `internal/modules/lesson/AGENT.md` (`last_verified`), `TODO.md`, and record in
`lesson/DECISIONS.md`: the `UnlockChecker` placement from Trap 2, and how a nil checker
